Crawling and robots.txt

Indexing and sitemap

Submit sitemap.xml in Google Search Console and fix coverage errors. Pages that are not indexed cannot rank.

Quick check: the indexed page count matches your page count.

Page speed

Pass Core Web Vitals with light pages and compressed images. Fast pages keep visitors and rank better.

Quick check: run PageSpeed Insights on mobile.

Use a responsive layout and one secure HTTPS version of every URL. Most searches happen on phones.

Canonical tags

Point duplicate URLs to the main one so ranking signals are not split.

Quick check: each page has one canonical URL.

Structured data

Add JSON-LD schema so search engines understand the page and can show richer results.

Quick check: validate with the Rich Results Test.
🔀

Redirects and status codes

Use 301 for permanent moves and avoid redirect chains. Fix 404 pages that still get links or traffic, and watch for 5xx server errors in Search Console.

Quick check: no important link ends in a 404 or a chain of redirects.
🏗️

Site structure and crawl depth

Keep important pages within about three clicks of the home page and link to them from related pages. Pages buried deep are crawled less and rank worse.

Quick check: every key page is linked from at least one other page.

Files and markup every site needs

Four things that help search engines and AI tools find and understand your site.

What is a sitemap (sitemap.xml)?

A sitemap is an XML file that lists the important pages of your site so search engines can find and crawl them faster. It lives at yoursite.com/sitemap.xml.

  • Include only pages you want indexed (status 200, no noindex).
  • Submit it in Google Search Console under Sitemaps.
  • Keep lastmod dates accurate and update it when pages change.
  • Add its address to robots.txt.
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-10-08</lastmod>
  </url>
</urlset>

What is robots.txt?

robots.txt is a text file at yoursite.com/robots.txt that tells crawlers which parts of your site they may visit. It controls crawling, not indexing.

  • Never write Disallow: / on a live site. It blocks everything.
  • Do not use it to hide private pages. Use a password or noindex instead.
  • Point to your sitemap with a Sitemap line.
  • You can allow or block AI crawlers such as GPTBot here.
User-agent: *
Allow: /

User-agent: GPTBot
Allow: /

Sitemap: https://example.com/sitemap.xml

What is llms.txt? (for AI and LLMs)

llms.txt is a proposed plain-text file at yoursite.com/llms.txt, written in Markdown. It gives large language models (LLMs) like ChatGPT and Gemini a short, clean summary of your site and links to your most important pages. It is a proposal, not an official standard, and no AI company promises to use it, but it costs almost nothing to add.

  • Start with the site name and a one-line summary.
  • List key pages with a short description each.
  • Keep it short and update it when pages change.
  • It does not replace robots.txt or good content.

What is schema markup?

Schema markup is structured data, written in the schema.org vocabulary and added as JSON-LD. It tells search engines and AI tools exactly what a page is about: a person, an article, a product or an FAQ. It can make pages eligible for rich results and helps machines understand your content.

  • Add JSON-LD in the page head.
  • Common types: Person, Organization, Article, FAQPage, BreadcrumbList, Product.
  • Markup must match what visitors can see on the page.
  • Test with Google's Rich Results Test and the Schema Markup Validator.
  • Google now shows FAQ rich results for only a few sites, but FAQ schema still helps machines read the page. See also AEO.
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Umair Tariq",
  "jobTitle": "SEO Specialist"
}
</script>

Canonical tags and Core Web Vitals

Two technical topics that protect your rankings and your visitors' experience.

What are canonical tags?

A canonical tag tells search engines which URL is the main version of a page when the same or very similar content is reachable at more than one address.

  • Common causes: http vs https, www vs non-www, URL parameters and trailing slashes.
  • Put a self-referencing canonical on every page.
  • Use one canonical per page and an absolute URL.
  • Never point a canonical to a redirected, noindex or 404 page.
  • It is a hint, not a command, so keep sitemap and internal links consistent with it.
  • Two different pages fighting for one keyword is a content problem. See keyword cannibalization.
<link rel="canonical" href="https://example.com/seo-audit">

What are Core Web Vitals?

Core Web Vitals are Google's three measures of real-world page experience: how fast the main content loads, how quickly the page responds, and how stable the layout is.

  • LCP: compress images (WebP or AVIF), preload the hero image and use a fast host or CDN.
  • INP: ship less JavaScript and defer scripts that are not needed straight away.
  • CLS: set width and height on images and reserve space for ads and embeds.
  • Measure with PageSpeed Insights, Lighthouse and the Core Web Vitals report in Search Console.
  • Scores use real user data, judged at the 75th percentile.

Common mistakes

  • Forgetting to submit the sitemap.
  • Leaving broken links and redirect chains.
  • Blocking CSS or JavaScript files.
  • Changing URLs without 301 redirects.

Frequently asked questions

What is technical SEO?

Technical SEO is the work that lets search engines crawl, render and index your site, such as sitemaps, robots.txt, speed, canonical tags and structured data.

Does robots.txt remove a page from Google?

No. robots.txt only controls crawling, so a blocked page can still be indexed if other sites link to it. Use a noindex tag to keep a page out of results.

Do I need llms.txt?

It is optional. It is a proposal that no major AI company guarantees to use, but it is cheap to add and helps explain your site.

What is a good Core Web Vitals score?

LCP of 2.5 seconds or less, INP of 200 milliseconds or less and CLS of 0.1 or less, for at least 75% of real visits.
